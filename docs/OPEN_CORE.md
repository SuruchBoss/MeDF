# โค้ดส่วนไหนอยู่ที่นี่ และส่วนไหนไม่อยู่

MeDF ส่วนใหญ่เป็น **MIT** อยู่ใน repo นี้ทั้งหมด — เอนจินวางทับ การจำแนกชั้นไฟล์
ท่อ export การฝังฟอนต์ไทย i18n และเปลือก PWA

สิ่งเดียวที่ไม่อยู่ที่นี่คือ **โมดูลแก้ข้อความเดิมในไฟล์** ซึ่งอยู่ใน repo ส่วนตัว
และต่อเข้ามาเป็น dependency ธรรมดา

## ทำไมถึงเป็นเส้นแบ่งนี้

เพราะมันคือสิ่งเดียวที่คู่แข่งราคา 0 บาททำได้ไม่ดี และเป็นสิ่งเดียวที่มีต้นทุนการสร้างจริง
(ดู [PRODUCT_DIRECTION.md](PRODUCT_DIRECTION.md) §5) จำนวนเอกสารหรือจำนวนครั้งที่ export
ไม่ใช่เส้นแบ่งที่ดี เพราะไม่มีเซิร์ฟเวอร์ให้นับ และเพราะมันไม่ได้แพงสำหรับใครเลย

## ไม่มี guard แล้ว

เมื่อก่อนที่นี่มีเครื่องจักรสามชั้น — `.gitignore` หลายบรรทัด, pre-commit hook
และขั้นแรกของ CI — คอยกันไม่ให้โค้ดที่เก็บเงินหลุดเข้ามา **ทั้งหมดถูกรื้อออกแล้ว**

เหตุผล: ของที่มันกันอยู่ไม่ได้อยู่ตรงนี้ตั้งแต่แรก โค้ดที่เก็บเงินได้รันในเบราว์เซอร์
และอยู่ในอีก repo หนึ่ง เครื่องจักรที่เหลือจึงกันช่องที่ไม่มีอะไรจะผ่าน
และเอกสารฉบับก่อนหน้าก็เขียนยอมรับข้อจำกัดนี้ไว้เองแล้ว

โมดูลที่ไม่ได้เผยแพร่ ก็แค่แพ็กเกจที่ไม่ได้เผยแพร่ ไม่ต้องมีพิธีกรรม

## สิ่งที่ซ่อนไม่ได้ และอย่าหลอกตัวเอง

โค้ดที่รันในเบราว์เซอร์ **ถูกอ่านได้เสมอ** ใครก็ตามที่เปิด DevTools เห็น bundle ทั้งก้อน
minify ไม่ใช่การเข้ารหัส การแยก repo ป้องกันการ *copy โครงการทั้งชุด* และทำให้
การขายต่อยากขึ้น แต่ไม่ได้ป้องกันคนที่ตั้งใจจะแกะจริง ๆ

เช่นเดียวกัน **ลายน้ำของแพ็กเกจฟรีบังคับในเบราว์เซอร์** จึงข้ามได้ด้วยการแก้ JavaScript
นี่เป็นการแลกที่ตั้งใจ ไม่ใช่ช่องโหว่ที่ลืม — คนที่ยอมแก้ JavaScript เพื่อเลี่ยงลายน้ำ
ไม่ใช่ลูกค้าที่หายไป

สิ่งที่ปกป้องรายได้จริง ๆ มีสองอย่าง และไม่ใช่เรื่องเทคนิคทั้งคู่

1. **กลุ่มเป้าหมายคือองค์กรที่ใช้ของเถื่อนไม่ได้** — มีนโยบาย IT โดนตรวจลิขสิทธิ์
   หรือมีบริษัทแม่ต่างชาติ คนกลุ่มนี้ต้องการใบเสร็จ ไม่ใช่ไฟล์ crack
2. **การที่ core เปิดให้ตรวจสอบได้** คือส่วนหนึ่งของเหตุผลที่องค์กรกล้าใช้ —
   พิสูจน์ได้ว่าไฟล์ไม่ถูกส่งออกไปไหน

## license key

ตรวจในเบราว์เซอร์ด้วย WebCrypto — key เซ็นด้วย ed25519 และฝังวันที่ "อัปเดตถึง" ไว้ข้างใน
ไม่มีเซิร์ฟเวอร์ตรวจสอบ ไม่มีการ phone home คนที่ซื้อไปแล้วใช้ได้ตลอดแม้เว็บนี้จะหายไป
