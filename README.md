# MeDF

**อัปโหลด PDF แล้วลากวางได้ทุกอย่าง — จัดเสร็จแล้ว Export กลับทันที**

และมีตัวติดตั้งสำหรับ Windows ที่ทำงานได้แบบออฟไลน์

## MeDF ทำอะไรได้

| ขั้นตอน | รายละเอียด |
| --- | --- |
| **1. อัปโหลด** | ลากไฟล์ PDF มาวาง หรือเลือกจากเครื่อง ระบบอ่านขนาดหน้าและจำนวนหน้าจริงจากไฟล์ |
| **2. แก้ไข** | ลากวาง ปรับขนาด หมุน จัดลำดับชั้น องค์ประกอบ 8 ชนิดได้อิสระบนทุกหน้า |
| **3. Export** | ได้ไฟล์ PDF ใหม่ที่ยังเป็นเวกเตอร์ ข้อความต้นฉบับยังคัดลอกและค้นหาได้ |

### องค์ประกอบที่วางลงหน้าเอกสารได้

- **กล่องข้อความ** — ฟอนต์ไทย (Sarabun) / Helvetica / Times / Courier, ตัวหนา-เอียง-ขีดเส้นใต้, จัดชิดซ้าย-กลาง-ขวา, สีตัวอักษรและพื้นหลัง, ระยะบรรทัด
- **รูปภาพ** — PNG / JPEG (ไฟล์ WebP, GIF, BMP จะถูกแปลงเป็น PNG ให้อัตโนมัติในเบราว์เซอร์)
- **ลายเซ็น** — วาดด้วยเมาส์ ปากกา หรือนิ้ว เก็บเป็นเส้นเวกเตอร์ที่ย่อ-ขยายได้ไม่เสียความคม
- **สี่เหลี่ยม / วงกลม** — กำหนดสีพื้น สีเส้นขอบ ความหนา และมุมโค้ง (ใช้กล่องสีขาวทับเพื่อลบข้อความเดิมได้)
- **เส้นและลูกศร** — ลากปลายเส้นได้อิสระ เลือกหัวลูกศรต้นทาง/ปลายทาง
- **ไฮไลต์** — ใช้โหมดผสมสีแบบ multiply จึงไม่ทับข้อความเดิมให้หายไป
- **เครื่องหมายถูก / ผิด / จุด** — สำหรับกรอกแบบฟอร์มและตรวจเอกสาร

### การทำงานในหน้าแก้ไข

- ลากวางอิสระ พร้อม **เส้นไกด์และ snap** เข้าขอบหน้า กลางหน้า และขอบขององค์ประกอบอื่น (กด `Alt` เพื่อปิด snap ชั่วคราว)
- **จุดจับ 8 ทิศ** สำหรับย่อ-ขยาย (กด `Shift` เพื่อคงสัดส่วน) และจุดจับหมุนอิสระ (กด `Shift` เพื่อหมุนทีละ 15°)
- **เลือกหลายชิ้น** ด้วยการลากคลุมหรือ `Shift`+คลิก, จัดตำแหน่งเทียบหน้ากระดาษ, สลับลำดับหน้า-หลัง, ล็อกองค์ประกอบ
- **แก้ไขข้อความในที่** ด้วยการดับเบิลคลิก โดยการตัดบรรทัดบนหน้าจอตรงกับในไฟล์ที่ export
- **จัดการหน้า** — สลับลำดับ หมุน ซ่อนหน้าที่ไม่ต้องการออกจากไฟล์ปลายทาง
- **undo / redo** ไม่จำกัดขั้น (80 ขั้นล่าสุด), **บันทึกอัตโนมัติ**, และคีย์ลัดครบ

### ระบบสมาชิกและการสมัครสมาชิก

- สมัครสมาชิก / เข้าสู่ระบบด้วยอีเมล (รหัสผ่านเข้ารหัสด้วย bcrypt, เซสชันเป็น JWT ใน cookie แบบ `httpOnly`)
- จำกัดจำนวนครั้งที่ลองเข้าสู่ระบบผิด, เปลี่ยนรหัสผ่านแล้วเซสชันทุกอุปกรณ์ถูกยกเลิก
- แพ็กเกจ **Free / Pro / Team** โดยโควตาทั้งหมด (จำนวนเอกสาร, ขนาดไฟล์, จำนวนหน้า, จำนวนครั้ง export, ลายน้ำ) ถูกบังคับที่ฝั่งเซิร์ฟเวอร์
- รองรับ **Stripe Checkout** จริง (พร้อม webhook สำหรับต่ออายุ ค้างชำระ และยกเลิก) หรือ **โหมดทดลอง** ที่เปลี่ยนแพ็กเกจได้ทันทีเมื่อยังไม่ได้ตั้งค่า Stripe
- หน้า **ผู้ดูแลระบบ** แสดงภาพรวมสมาชิก การใช้งาน และรายรับ (สมาชิกคนแรกของระบบได้สิทธิ์ admin อัตโนมัติ)

## สองชั้น: ฟรีเป็นโอเพนซอร์ส · ฟีเจอร์เสริมเป็นของปิด

MeDF ใช้โมเดล **open core**

| | ฟรี | ฟีเจอร์เสริมแบบชำระเงิน |
| --- | --- | --- |
| โค้ด | อยู่ใน repository นี้ อ่าน fork และ self-host ได้ | อยู่ใน repository ส่วนตัวแยก **ไม่เคยถูก push เข้าที่นี่** |
| ผู้ที่จ่ายเงิน | — | ได้ **ใช้ฟีเจอร์** ไม่ได้รับโค้ด |
| ถ้าไม่มีโมดูลเสริม | ทำงานครบตามปกติ | ฟีเจอร์นั้นไม่ปรากฏและเรียกไม่ได้ (`501`) |

repo นี้เปิดเผยเพียง **ชื่อฟีเจอร์** (ลูกค้าต้องรู้ว่าจ่ายเพื่ออะไร) และ **รูปร่างของ interface**
ส่วนวิธีทำงานอยู่ในโมดูลที่โหลดตอนรัน — ดู `apps/web/src/lib/features.ts` และ `apps/web/src/lib/pro.ts`

การรับประกันว่าโค้ดที่เก็บเงินไม่หลุดเข้า git มีสามชั้น: `.gitignore`,
pre-commit hook (`npm run setup:hooks`) และขั้นตอนแรกของ CI — ทั้งหมดเรียก `npm run guard:private`
ซึ่งจะ fail ถ้าพบไฟล์ของชั้นที่ชำระเงินอยู่ใน staging หรือ tracked files

> โค้ดที่รันบน **เซิร์ฟเวอร์** ซ่อนจากผู้ใช้ที่จ่ายเงินได้จริง เพราะไม่ถูกส่งไปเบราว์เซอร์
> แต่โค้ดที่รัน **ในเบราว์เซอร์** ผู้ที่ได้รับไปย่อมอ่านได้เสมอ (ข้อจำกัดของเว็บ ไม่ใช่ของ MeDF)
> จึงควรวางตรรกะที่เป็นมูลค่าไว้ฝั่งเซิร์ฟเวอร์ รายละเอียดทั้งหมดอยู่ใน
> [`docs/OPEN_CORE.md`](docs/OPEN_CORE.md)

| วิธี | ต้องทำอะไร | ได้อะไร |

## เริ่มใช้งาน

```bash
git clone https://github.com/SuruchBoss/MeDF.git
cd MeDF
npm install
npm run setup:hooks   # ติดตั้ง pre-commit hook กันโค้ดชั้นที่ชำระเงินหลุดเข้า repo

# ตั้งค่า (ไม่บังคับสำหรับการพัฒนา — มีค่าเริ่มต้นให้ทั้งหมด)
cp apps/web/.env.example apps/web/.env.local

npm run dev          # เปิดที่ http://localhost:4173
```

สมาชิกคนแรกที่สมัครจะได้สิทธิ์ผู้ดูแลระบบ และข้อมูลทั้งหมดถูกเก็บไว้ที่โฟลเดอร์ `.medf-data/`

### สร้างเวอร์ชันสำหรับใช้งานจริง

```bash
npm run build        # สร้าง Next.js แบบ standalone
npm run start        # รันเซิร์ฟเวอร์ที่พอร์ต 4173
```

### ติดตั้งบน Windows

```bash
npm run dist:win              # ได้ตัวติดตั้ง NSIS (.exe) ใน desktop/dist
npm run dist:win:portable     # ได้เวอร์ชัน portable ที่ไม่ต้องติดตั้ง
```

ดูรายละเอียดทั้งหมด (รวมถึงการสร้างตัวติดตั้งจากเครื่อง Linux/macOS และผ่าน GitHub Actions)
ได้ที่ [`docs/WINDOWS.md`](docs/WINDOWS.md)

### เผยแพร่เว็บเดโมบน GitHub Pages

```bash
npm run demo:build    # ได้ไฟล์สถิตที่ apps/demo/out
npm run test:static   # ทดสอบแบบที่ Pages จะเสิร์ฟจริง
```

เปิดใช้ครั้งแรกต้องตั้ง **Settings → Pages → Source = GitHub Actions** หนึ่งครั้ง
รายละเอียดอยู่ใน [`docs/PUBLIC_DEMO.md`](docs/PUBLIC_DEMO.md)

## การตั้งค่า

ทุกค่ามีค่าเริ่มต้นที่ใช้พัฒนาได้ทันที รายละเอียดทั้งหมดอยู่ใน [`apps/web/.env.example`](apps/web/.env.example)

| ตัวแปร | ความหมาย |
| --- | --- |
| `MEDF_SESSION_SECRET` | กุญแจเซ็นเซสชัน — **ต้องตั้งค่าเมื่อใช้งานจริง** |
| `MEDF_DATA_DIR` | โฟลเดอร์เก็บสมาชิก เอกสาร และไฟล์ที่อัปโหลด |
| `MEDF_APP_URL` | URL สาธารณะ ใช้กับการ redirect ของ Stripe |
| `MEDF_BILLING_SANDBOX` | `1` เพื่อเปิดโหมดทดลองระบบชำระเงิน (เปิดอัตโนมัติเมื่อไม่ได้ตั้งค่า Stripe) |
| `MEDF_ADMIN_EMAIL` | อีเมลที่จะได้สิทธิ์ admin เมื่อสมัคร |
| `MEDF_PRO_MODULE` | path ของโมดูลฟีเจอร์เสริม (ถ้าไม่ตั้ง จะทำงานเป็นบิลด์โอเพนซอร์สล้วน) |
| `NEXT_PUBLIC_BASE_PATH` | คำนำหน้า URL เมื่อโฮสต์ใต้ subpath (เว็บสถิตบน Pages ใช้ `/MeDF`) |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_*` | เปิดการชำระเงินจริงผ่าน Stripe |

## โครงสร้างโปรเจกต์

```
MeDF/
├── apps/demo/                    # เว็บสถิตสำหรับ GitHub Pages (Landing + /try)
│                                 #   ใช้คอมโพเนนต์ชุดเดียวกับ apps/web
├── apps/web/                     # เว็บแอป Next.js (App Router)
│   ├── src/app/                  # หน้าเว็บและ API routes
│   │   ├── page.tsx              #   landing page
│   │   ├── pricing/              #   หน้าแพ็กเกจ
│   │   ├── login/ register/      #   ระบบสมาชิก
│   │   ├── app/                  #   ส่วนที่ต้องเข้าสู่ระบบ (แดชบอร์ด บิล บัญชี admin)
│   │   │   └── editor/[id]/      #   หน้าแก้ไขเอกสาร
│   │   └── api/                  #   auth, documents, assets, billing, health
│   ├── src/components/editor/    # หน้าแก้ไข: state, การลากวาง, แผงคุณสมบัติ
│   │   └── backend.ts            #   ตัวเชื่อม: ใช้ API หรือทำงานในเบราว์เซอร์ล้วน
│   ├── src/components/demo/      # หน้า “ลองใช้ทันที” (ไม่ต้องสมัคร)
│   ├── src/lib/                  # ชั้นข้อมูล สิทธิ์ โควตา แพ็กเกจ
│   │   ├── features.ts           #   ทะเบียนฟีเจอร์: อะไรฟรี อะไรต้องจ่าย
│   │   ├── pro.ts                #   ตัวโหลดโมดูลฟีเจอร์เสริม + ประตูตรวจสิทธิ์
│   │   └── pdf/                  # เครื่องมือ export (pdf-lib + ฟอนต์ + เมทริกซ์)
│   ├── public/fonts/             # ฟอนต์ Sarabun (ใช้ทั้งบนจอและฝังใน PDF)
│   └── scripts/                  # เทสต์ end-to-end และสคริปต์ build
├── desktop/                      # เชลล์ Electron + ตัวติดตั้ง Windows
├── scripts/                      # guard โค้ดชั้นที่ชำระเงิน · git hooks · scaffold
└── docs/                         # สถาปัตยกรรม · open core · เว็บเดโม · Windows · การ deploy
```

อ่านที่มาที่ไปของการออกแบบ (ระบบพิกัด 3 ชั้น, ชั้นข้อมูล, ขั้นตอน export)
ได้ที่ [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)
